## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model/agent → `fdars_compare_run` | Model-supplied `before_result_id`, `method`, and after-params drive a real fdars re-run and diff |
| tool handler → HandleRegistry | before/after result handles resolve to in-process arrays/dicts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02 | Tampering | `fdars_compare_run` / `compare_run` `method` arg | high | mitigate | Validate `method` against the closed set at the tool boundary and again in the runner; `ValueError` on unknown method (V5) |
| T-12-03 | Tampering | `params_after` keys | high | mitigate | Allowlist-validate `params_after` keys against `{lambda_, n_basis, n_comp, k, seed}`; reject unknown keys with `ValueError`; only scalar values accepted (no arrays) |
| T-12-01 | Tampering | `registry.get_result(before_result_id)` | medium | mitigate | Unknown `before_result_id` raises `KeyError` surfaced as a tool execution error (fail closed) |
| T-12-06 | Repudiation | fabricated (non-fdars) numbers in delta | high | mitigate | delta is computed solely from `build_diagnostics` outputs on real fdars re-runs; no LLM in the compare path — grounding invariant holds and is asserted by the delta-sign test |
</threat_model>
