    Create a new page `docs/advisor/providers.md` titled "Provider Setup"
    (H1 `# Provider Setup`). Follow the existing advisor-page tone (see
    index.md / python-api.md) and STYLE_SPEC prose conventions. Per DOCS-01,
    document all four backends and the selection rules. Structure:

    1. Intro paragraph: the advisor routes every LLM call through a uniform
       `Provider` protocol; `advise(provider=, model=)` is the only entry point
       for provider selection (the MCP tools are compute-only and never call
       `advise()`). Reuse the framing from SKILL.md "Provider Selection".

    2. A "Backends" section with one subsection per backend, each stating the
       provider name string, the required package/extra, and the credential:
         - Anthropic — DEFAULT; provider name `"anthropic"`; extra
           `pip install "fdars[advisor]"`; env `ANTHROPIC_API_KEY`.
         - OpenAI and OpenAI-compatible — provider name `"openai"`; extra
           `pip install "fdars[openai]"`; env `OPENAI_API_KEY`; note the
           configurable `base_url` (via `FDARS_ADVISOR_BASE_URL` or the
           equivalent kwarg) for vLLM / LM Studio / LocalAI endpoints.
         - Google Gemini — provider name `"gemini"`; extra
           `pip install "fdars[gemini]"`; package `google-genai`; note the
           Python 3.10+ requirement; env `GOOGLE_API_KEY` (or the SDK's
           standard key variable).
         - Local Ollama — provider name `"ollama"`; extra
           `pip install "fdars[ollama]"`; NO API key required; requires a
           running Ollama daemon; default endpoint `http://localhost:11434`.
       Mention the umbrella extra `pip install "fdars[all-providers]"` that
       pulls every provider adapter at once.

    3. A "Selection and precedence" section stating the resolution order taken
       from advise()/resolve_provider in python/fdars/advisor/__init__.py:
       explicit `advise(provider=, model=)` parameters take precedence, then the
       environment variables, and `provider=None` reproduces the Anthropic
       default exactly. Include the env-var table reused from SKILL.md with the
       three variables FDARS_ADVISOR_PROVIDER, FDARS_ADVISOR_MODEL,
       FDARS_ADVISOR_BASE_URL (same purpose/example columns), plus a row-per
       note that each provider also reads its own API-key variable.

    4. An "Install extras" reference table mapping each provider name to its
       extra and key requirement (anthropic→[advisor]/ANTHROPIC_API_KEY,
       openai→[openai]/OPENAI_API_KEY, gemini→[gemini]/GOOGLE_API_KEY +3.10,
       ollama→[ollama]/none). Note the base package imports and the offline
       core (`build_diagnostics`) runs with no provider extra installed, and a
       missing extra raises an actionable ImportError.

    Keep every value method-accurate against SKILL.md and __init__.py — do NOT
    invent env-var names, extra names, or model strings. Where SKILL.md and this
    page overlap (env table, precedence prose), the wording MUST stay consistent.
