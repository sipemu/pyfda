    Define the class per D-01 discretion: `#[pyclass(name = "PyMultiFunData")] pub struct PyMultiFunData
    { pub inner: fdars_core::multi_fdata::MultiFunData }`.

    Define `#[pyfunction] pub fn multi_fdata_from_components<'py>(py, data_list: &Bound<'py, PyList>,
    argvals_list: &Bound<'py, PyList>) -> PyResult<Py<PyMultiFunData>>`. Builder logic:
    (1) Guard both lists are equal length; on mismatch raise PyValueError naming the two counts.
    (2) For each index k: reject a 1D data element (cast data_list[k] to numpy::PyUntypedArray and check
        ndim()==1, raising PyValueError pointing to the dense-2D-matrix requirement — the inverse of
        pace_fpca's 2D-reject guard); downcast data_list[k] to PyReadonlyArray2<f64> and convert via
        numpy2d_to_fdmatrix; downcast argvals_list[k] to PyReadonlyArray1<f64> and convert via
        numpy1d_to_vec; build `fdars_core::multi_fdata::FdComponent { data: mat, argvals: av }`.
    (3) `let inner = to_pyresult(fdars_core::multi_fdata::MultiFunData::new(components))?;` — the core
        constructor validates non-empty, shared nrows across components, and argvals.len()==data.ncols();
        to_pyresult surfaces FdarError as PyValueError (so the mismatched-nrows case becomes a Python
        ValueError).
    (4) `Py::new(py, PyMultiFunData { inner })`.

    Add `#[pymethods] impl PyMultiFunData` with two getters delegating to inner: n_obs and n_components.

    Add `pub fn register(m: &Bound<'_, PyModule>) -> PyResult<()>` calling
    `m.add_class::<PyMultiFunData>()?` and `m.add_function(wrap_pyfunction!(multi_fdata_from_components, m)?)?`.

    Use explicit imports only (CI runs -D warnings — no unused imports). Follow pace_fpca_mod.rs import
    style (numpy::PyUntypedArrayMethods for .ndim(), pyo3::types::PyList, the specific convert:: helpers used).

    In `src/lib.rs`: add `mod multi_fdata_mod;` after `mod density_fda_mod;` (line 33 region), and add
    `register_submodule!(m, "multi_fdata", multi_fdata_mod::register);` after the density_fda
    register_submodule! call (line 70 region, before `Ok(())`).

    In `python/fdars/__init__.py`: append a `"multi_fdata"` entry (with a Phase-70 comment) to the
    `_submodule_names` tuple after the `"density_fda"` entry.
