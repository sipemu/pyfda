EXACT API CALLS (RESEARCH 1.4 — all VERIFIED against src/fts_mod.rs; honor gotchas):
- `fit = ftsm(X_train, t_wk, ncomp=3)` — dict with keys mean/rotation/scores/fitted/weights/ncomp/ar_models.
- Variance explained MUST be computed from scores, NOT weights (RESEARCH pitfall 5 — `weights` is a per-grid-point (m,) array, not PVE): `scores = np.asarray(fit["scores"]); pve = 100 * scores.var(axis=0) / scores.var(axis=0).sum()`. - Show the per-component AR orders by reading `fit["ar_models"]` (list of dict with `order`).

- RMSE: `rmse = np.sqrt(np.mean((fcast - X_test)**2))`.
- `stationarity_test(X_train, t_wk, n_perm=fast(999, 99), seed=42)` → dict with `p_value` (~0.010). Gate n_perm with `fast(999, 99)` so the strict build stays bounded (RESEARCH 1.6).
- `functional_acf(X_train, t_wk, max_lag=8, n_sim=fast(999, 99), seed=42)` → dict with `lags`/`acf`/`pacf`/`upper_band`. functional_acf is slow on the full 365-pt grid (~4.8s) — the weekly (30,52) data runs in ~0.028s (RESEARCH pitfall 6); the weekly aggregation is REQUIRED for a bounded fence.
