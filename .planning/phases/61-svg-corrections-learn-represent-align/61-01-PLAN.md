## Accessibility markup contract (apply identically to every one of the 24 SVGs)

Per D-A11Y-02 and D-A11Y-01 in 61-CONTEXT.md and the STYLE_SPEC "Accessibility Pattern" section, each diagram must gain an in-document `<title>` + `<desc>` wired to the root `<svg>` via `aria-labelledby`, and its root `aria-label` must be corrected to match the visible `.ttl` title text.

**The exact pattern (adapt id-prefix per file, wording per diagram):**
- Give the root `<svg>` two new attributes: `aria-labelledby="<slug>-title <slug>-desc"` where `<slug>` is the filename stem (e.g. `shift-registration`). Keep `role="img"`.
- Correct the existing `aria-label` on the root `<svg>` so its text equals the diagram's visible `.ttl` title text, character-for-character (decode HTML entities — e.g. `&#8211;` renders as an en-dash, `&#215;` as `×`, `&#948;` as `δ`; the aria-label attribute value should contain the DECODED character or a faithful equivalent, and must not be a paraphrase). Retaining `aria-label` alongside `aria-labelledby` is intentional as a fallback; `aria-labelledby` wins in AT precedence.
- Immediately after the `<svg ...>` opening tag (before or right after the `<style>` block — position is executor discretion but keep it near the top), insert:
  - `<title id="<slug>-title">…</title>` — the concise diagram name (the `.ttl` text).
  - `<desc id="<slug>-desc">…</desc>` — one to two sentences describing WHAT the diagram depicts and WHICH method/behavior it illustrates. Write real, method-accurate prose grounded in the audit §1 Notes for that diagram — NOT a generic placeholder.

**id uniqueness:** ids must be unique within the file. Use the `<slug>-title` / `<slug>-desc` convention so no collision with existing element ids (existing ids use short names like panel/curve labels).

**Method-accuracy of `<desc>` (DEFECT-03 hard gate):** the `<desc>` sentence MUST describe the method correctly. Cross-check each against the 60-AUDIT.md §1 row Notes for that diagram (they record exactly what each panel depicts and which fdars function is shown). Do not invent behavior. Example for shift-registration: describe rigid horizontal translation by a scalar δ to the cross-sectional mean — NOT warping.

**STYLE_SPEC / SVGO (SPEC-01, do-not-regress):**
- Do NOT change viewBox, the `<style>` block, palette hexes, font stack, stroke weights, or panel rects.
- `<title>`/`<desc>` are standard SVG elements and are SVGO-idempotent — do not add scripts, comments-as-structure, or duplicate ids.
- Leave any pre-existing per-element deviations alone (e.g. depth-functions.svg's `.ttl` carries an inline `font-size="20" style="fill:#333"` — the audit scored it STYLE_SPEC OK; do NOT "fix" it, that would be an out-of-scope typography change).
