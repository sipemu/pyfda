<objective>
Expose fdars-core 0.23's sparse/irregular PACE FPCA and its K-class elastic multinomial classifier to Python: a NEW `src/pace_fpca_mod.rs` carrying pyfda's FIRST `#[pyclass]` (`PyIrregFdata`, wrapping `fdars_core::irreg_fdata::IrregFdata`), the `fdars.irreg_fdata_from_lists` builder, and `fdars.pace_fpca`; plus `fdars.classification.elastic_multinomial` extending the existing `fdars.classification` submodule (per D — CONTEXT.md locked decisions PACE-01/PACE-02/CLASS-01).

The first task is an end-to-end tracer that front-loads the milestone's one no-precedent architectural risk — pyfda has never used a `#[pyclass]` opaque handle — by wiring the `PyIrregFdata` class + `irreg_fdata_from_lists` + a minimal `pace_fpca` round-trip through every layer (list extraction → IrregFdata construction → `#[pyclass]` handle → by-ref consumption in `pace_fpca` → PyDict → module registration → importable Python smoke) BEFORE expanding to full validation, converters, guards, and the independent classifier.

Purpose: Deliver PACE-01 (the ragged `IrregFdata` input path with dense/ragged-mismatch `ValueError` guards), PACE-02 (the 10-key `pace_fpca` dict with `eigenfunctions (m,ncomp)` / `scores (n,ncomp)` transposition-guarded and `actual_ncomp` truncation handled), and CLASS-01 (`elastic_multinomial` with the CR-01 label guard, `train_probabilities (n,K)` guarded, `class_models` omitted) — proving the `#[pyclass]` architecture on one path first so a binding dead-end surfaces after one commit, not five.
Output: A new `src/pace_fpca_mod.rs` (`PyIrregFdata` class + `irreg_fdata_from_lists` + `pace_fpca` + two `*_to_pydict` converters + an `extract_list_of_vecs` helper + `register()`), an extended `src/classification_mod.rs` (`elastic_multinomial` + its converter), edits to `src/lib.rs` and `python/fdars/__init__.py` registering the new submodule, and new/extended `tests/test_pace_fpca.py` + `tests/test_classification.py`.
</objective>
