Create `python/fdars/advisor/providers/gemini.py` beginning with `from __future__ import annotations` only at top level (SDK imports deferred; Pitfall 4). Implement the translation helpers as module-level functions (per 20-RESEARCH.md §Gemini Pydantic->Schema Translation; D: PROV-05):

`_gemini_schema(model_cls)`: deepcopy `model_cls.model_json_schema()`; pop `$defs` into a local map; call `_resolve_refs(schema, defs)` to inline every `$ref` (Gemini does not support $ref); then `_strip_key(schema, "additionalProperties")` (google-genai's client validator rejects it, even though the API supports it — Pitfall 1) and `_strip_key(schema, "title")` (lean payload). Return the transformed dict.

`_resolve_refs(obj, defs)`: recursive — when a dict has a `$ref`, take the trailing name after the last `/`, deepcopy the matching entry from defs, and recurse into the resolved value; otherwise recurse into dict values / list items; return scalars unchanged.

`_strip_key(obj, key)`: recursively pop `key` from every nested dict and recurse into dict values / list items.

The Literal["parameter","method","none"] field serialises to `{"enum": [...], "type": "string"}` which Gemini accepts unchanged — no special handling needed. (GeminiProvider class comes in Task 2 of this plan; keep it in the same file, but this task delivers only the helpers so they can be tested before the adapter.)

Then create `tests/test_advisor_gemini_schema.py` — offline, pydantic-only, NO SDK mock needed (the helper never imports the SDK). Tests: additionalProperties stripped (assert substring absent in json.dumps), $ref/$defs absent, kind enum preserved at the nested path, and required arrays present on root + Recommendation.
