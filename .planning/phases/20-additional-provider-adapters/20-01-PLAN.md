<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter -> OpenAI/compat endpoint | prompt + schema sent to a remote (or local) LLM; response is untrusted until schema-validated + grounding-checked |
| local compat endpoint (base_url) | user-supplied base_url may point at an untrusted local service; dummy key avoids leaking real OPENAI_API_KEY to it |
| pip install (extras) | new package dependencies enter the supply chain |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-01 | Tampering | LLM response content | high | mitigate | native schema validation (model_validate_json) + centralized `_check_grounding` reject fabricated numbers; refusal/empty raise ValueError |
| T-20-02 | Information disclosure | api_key vs base_url | medium | mitigate | localhost base_url with no explicit key sends dummy `none`, never a real OPENAI_API_KEY, to local endpoints |
| T-20-03 | Denial of service | malformed model output | low | accept | ValueError surfaces cleanly to caller; no retry storm (native path returns once) |
| T-20-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy audit in 20-RESEARCH.md (openai/google-genai/ollama all official, Approved); no [ASSUMED]/[SUS]/[SLOP] packages |
</threat_model>
