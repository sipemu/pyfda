The doc MUST contain these sections:

1. **Purpose & scope** — `_references_map.json` is the paper-level provenance side-file for fdars callables; it is authored by hand and validated by GATE-05 guard tests. State the hard rule up front: the schema is never authored free-form; every entry is validated from day one.

2. **File location & packaging** — `python/fdars/_references_map.json`, loaded via `importlib.resources`; note that files directly under `python/fdars/` ship in the wheel automatically (no maturin `include` entry needed — verified against `_capability_map.json`/`_capability_curation.json`).

3. **Identifier space** — keys are `"module.callable"` (exactly one dot) in the SAME space as `_capability_curation.json`; Fdata class methods use the `"_Fdata.<method>"` special case; every callable claimed MUST resolve in `_capability_map.json` (GATE-05 B enforces this).

4. **Top-level shape** — two keys: `papers` (object keyed by ASCII slug like `fraiman_muniz_2001`) and `callable_index` (flat `"module.callable"` → array of paper keys). State the internal-consistency invariant verbatim: `frozenset(callable_index.keys()) == frozenset(c for p in papers.values() for c in p["callables"])` (GATE-05 A). Both directions must be edited together (Pitfall 5).

5. **`papers[*]` field table** — document every field with type + required flag + notes, matching the shipped file: title, authors (`"LastName, Initials."` ordered as in paper), year (integer, publication not preprint year), doi (matches `^10\.\d{4,9}/\S+$`, omit `doi:`/`https://doi.org/` prefix, omit entirely for preprints), url (canonical landing page), type (journal/conference/preprint/book/book_chapter), callables (array of resolvable identifiers), cross_language (optional object), notes (optional), curated (boolean).

6. **`cross_language[*]` shape** — keys are `"R"`/`"Python"`/`"Matlab"`; fields package, function, version (optional, pin the verified-against version), url (points to SPECIFIC function docs, not a package homepage), confidence (`"high"` = personally verified, `"low"` = inferred). State the locked rule: **Matlab entries default to `confidence: "low"` unless personally verified.** Honest "no implementation in language X" gaps are recorded by simply omitting that language key.

7. **The `curated:false` tail convention** — for callables known to need a reference but not yet curated, add an entry with `curated: false` (empty/null bibliographic fields allowed) whose `callables` list carries the pending identifiers. GATE-05 A only checks index↔papers consistency, not `curated` status, so `curated:false` entries do not break the guard. Note that anti-feature families (Phase 81) are wired to this sentinel path rather than force-cited. The Plan-01 stub ships NO `curated:false` entries — this convention is for Phase 81 onward.

8. **Sub-method-keyed attribution rule** — attribution is per sub-method, never one paper blindly spread across a family: `depth.band_1d` and `depth.modified_band_1d` are BOTH introduced in López-Pintado & Romo 2009 (same paper key is correct there), but band depth ≠ a different depth variant in general. Contested/multi-primary attributions list co-primaries or are flagged in `notes` rather than force-picked.

9. **Author-verification workflow (the hard bar)** — an entry may set `curated: true` ONLY after the curator has personally opened the DOI landing page and confirmed author list, year, and title against it. A resolving DOI is NOT proof of correct attribution. Include the canonical worked example: Fraiman–Muniz depth is 2001 (TEST journal, DOI `10.1007/BF02595706`), NOT 1991 — 1991 is Ramsay–Dalzell (`10.1111/j.2517-6161.1991.tb01844.x`). Also flag the SRSF-vs-SRV pitfall: use arXiv:1103.3817 for functional-data SRSF alignment, not the TPAMI SRV/shape paper.

10. **What the guards enforce (GATE-05)** — one short subsection each for A (internal consistency), B (cross-file resolution against `_capability_map.json`), and C (structural DOI regex + URL well-formedness + domain allowlist, offline; live resolve opt-in via `FDARS_ONLINE_CHECKS=1`, never in CI/mkdocs). Point curators at `tests/test_guard_sync_version_independent.py` (Group 3) and give the run command `pytest tests/test_guard_sync_version_independent.py -v`.

Keep prose accurate to the shipped file — if the Plan-01 stub differs from any shape described in RESEARCH (e.g. a callable was dropped because it did not resolve), document what actually shipped.
