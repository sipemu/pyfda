<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Python caller → PyO3 wrapper | Untrusted numpy arrays, grid vectors, policy/method strings, and scalar params cross into Rust. |
| PyO3 wrapper → fdars-core | Marshalled FdMatrix + enum selections cross into the compute engine. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-01 | Tampering | fdmatrix→numpy return path (spline_interpolate, *_with_policy, impute) | high | mitigate | Route every matrix return through `convert::fdmatrix_to_numpy2d`; guard with a distinct-per-curve multi-curve round-trip test (Pitfall 1 / #33 class). |
| T-26-02 | Denial of Service | fallible core calls (OOD query, all-NaN row, bad policy string) | medium | mitigate | Wrap every `Result` with `to_pyresult()`; NO `.unwrap()` in `represent_mod.rs`; add `pytest.raises(ValueError)` tests for OOD-exception, all-NaN, and invalid policy/method strings. |
| T-26-03 | Tampering | ExtrapolationPolicy/ImputationMethod string dispatch | medium | mitigate | Exhaustive `match` with a `_ => Err(PyValueError)` fallback arm (upstream enums are `#[non_exhaustive]`); reject unknown strings rather than silently defaulting. |
| T-26-SC | Tampering | npm/pip/cargo installs | low | accept | No new package installs — `fdars-core 0.17.0` already pinned and audited in Phase 25; this plan adds only bindings. |
</threat_model>
