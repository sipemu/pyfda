<objective>
Add the fdars-core 0.20 basis/smoothing quick wins as additive PyO3 bindings: `constant_basis` (all-ones intercept column), `smooth_basis_aic` (AIC-optimal basis roughness penalty), and AIC kernel-bandwidth selection via `optim_bandwidth(criterion="aic")`. Covers BASIS-01, BASIS-02, BASIS-03.

Output: Extended `src/basis_mod.rs` (`constant_basis` + `smooth_basis_aic`), fixed `src/smoothing_mod.rs` (`optim_bandwidth` AIC input dispatch + output arm), and a new `tests/test_basis_smoothing.py`.

## Placement decision (Claude's Discretion, per 33-CONTEXT.md)
The 33-CONTEXT prose names `fdars.smoothing.smooth_basis_aic`, but the closest existing analog `smooth_basis_gcv` is registered in `basis_mod::register` and is publicly `fdars.basis.smooth_basis_gcv` (all docs at `docs/learn/derivatives.md` and `advisor/aspects/smoothing.py` call `fdars.basis.smooth_basis_gcv`). To keep the AIC twin next to its GCV analog, `smooth_basis_aic` is bound in `src/basis_mod.rs` and exposed as `fdars.basis.smooth_basis_aic`. This is the "follow the closest existing analog" placement the CONTEXT explicitly delegates to plan/execute time. `basis_nbasis_cv` already lives in `basis_mod.rs`. Only `optim_bandwidth` (kernel bandwidth) is in `smoothing_mod.rs`.
