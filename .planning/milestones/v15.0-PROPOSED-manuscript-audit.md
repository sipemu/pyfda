# PROPOSED Milestone — Deeper Manuscript Audit (scientific-writing skill)

**Status:** PROPOSED (not started). Do NOT begin until v14.0 ships
(GATE-04 approved → tag `v0.13.0` pushed → PyPI). This is the candidate *next*
milestone after the fdars Software Paper (v14.0).

**Created:** 2026-09-12, from the `k-dense-ai/scientific-writing` skill audit.

## Why

The `k-dense-ai/scientific-writing` skill (installed globally at
`~/.claude/skills/scientific-writing`, symlinked from
`~/.dhub/skills/k-dense-ai/scientific-writing`; offline, network-free, stdlib-only,
audit grade C = "unscanned files" only, scripts vetted clean) ships offline CLIs
that can audit the manuscript far more deeply than we have so far. In the first
pass we only ran the two reference CLIs (`validate_manifest`, `check_references`)
over a manifest built from `refs.bib`+`refs_manual.bib`:
- Result: **no duplicate DOIs/URLs/titles** across 52 refs (clean).
- One real finding — the uncited provenance entry `nadaraya_watson_1964` had an
  empty title — **already fixed** this session (title added from the verified
  notes; `refs.bib` regenerated; drift gates green).

The three deeper CLIs were **not** run because they need the skill's structured
Markdown-manuscript + claim/evidence + consistency registries, which we do not
yet have for the LaTeX paper.

## Goal

Build the skill's registries for `paper/` and run its full audit chain, then fix
every real finding — giving the software paper a claim→evidence provenance audit
consistent with fdars's own grounded-provenance ethos.

## Scope / work items

1. **Claim & evidence registry** — extract the paper's factual/numeric claims
   (coverage counts, R²/RMSE, CV scores, cluster sizes, MUOD counts, PM10 RMSE,
   FPCA variance %, DTW value, `n=…`, dataset shapes, etc.) into the skill's
   `claims.csv` (headers: `claim_id,section,claim_kind,claim_text_sha256,`
   `evidence_ids,verification_status,uncertainty,analysis_intent`) and a
   `source_manifest.json` (E-IDs; the bib→manifest converter draft is in the
   session scratchpad — re-derive it; it double-brace-misparsed `{{...}}` titles,
   fix that). Bind each numeric claim to its live source (script output / dataset
   / cited paper).
2. **Run `audit_claims.py`** (`manuscript.md claims.csv source_manifest.json`)
   over a Markdown rendering of the paper — flags numeric content lacking a claim
   marker and unverified claims.
3. **Run `check_consistency.py`** over a `consistency_manifest.json` of repeated
   numeric facts + method↔result mappings — catches the same number stated
   differently across §4 / case studies / captions / abstract.
4. **Run `lint_manuscript.py`** — placeholder/language/sensitive-content lint.
5. **Fix findings**; keep the CI `paper.yml` gates (tectonic + real-pdflatex
   arxiv job, drift gates, 0 overfull>20pt) green throughout.
6. Optionally wire a lightweight version of these checks into `make paper-check`.

## Constraints / notes

- All skill CLIs are offline/deterministic; run from the skill dir with py3.11+.
- Honor the skill's **no-fabrication** rule: never invent a title/DOI/number —
  mark unverified. (That is why `nadaraya_watson_1964` used its documented notes.)
- Numbers in the paper are computed live by `paper/code/*.py`; the registry must
  bind to those, not hardcode.
- The converter/manifest scratch lived under the session scratchpad (ephemeral);
  re-create under `paper/audit/` if this milestone runs, and consider committing
  the registries so the audit is reproducible.
