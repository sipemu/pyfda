<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model/agent → MCP tool call | Model-supplied `dataset_id`, `method`, and params cross into fdars compute; untrusted strings/values |
| tool handler → HandleRegistry | Opaque handle IDs resolve to in-process numpy arrays; unknown IDs must fail closed |
| build tooling → PyPI (`mcp` install) | Third-party package installed into the dev/CI environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Tampering | `HandleRegistry.get_dataset/get_result` | medium | mitigate | Unknown `dataset_id`/`result_id` raises `KeyError` naming the offending id; the tool surfaces it as an execution error (fail closed) — asserted in Plan 02/03 error tests |
| T-12-02 | Tampering | `fdars_build_diagnostics` `method` arg | high | mitigate | Validate `method` against the closed set `{"alignment","fpca","basis","smoothing","clustering"}` before any fdars call; raise `ValueError` on unknown method (V5 input validation) |
| T-12-05 | Info Disclosure | HandleRegistry lifetime | low | accept | In-process, single-session local/CI use; registry cleared per-test via autouse fixture; no cross-user exposure in stdio scope |
| T-12-SC | Tampering | `pip install mcp` | high | mitigate | Package-legitimacy `[SUS]` verdict → blocking-human checkpoint before install; verified against pypi.org/project/mcp and the modelcontextprotocol GitHub org |
</threat_model>
