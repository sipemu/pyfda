| tool handler → HandleRegistry | Dataset/result handle IDs resolve to in-process numpy arrays |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02 | Tampering | `_runner.run_method` / `fdars_run_method` `method` arg | high | mitigate | Validate `method` against `{"alignment","fpca","basis","smoothing","clustering"}` before any fdars call; `ValueError` on unknown method (V5) |
| T-12-03 | Tampering | `fdars_run_method` params | high | mitigate | Params are flattened top-level typed scalars (`float`/`int`/`None`); no `dict`/array param accepted — MCP schema fully constrains inputs (Pitfall 6) |
| T-12-01 | Tampering | `registry.get_dataset/get_result` | medium | mitigate | Unknown handle IDs raise `KeyError` and surface as tool execution errors (fail closed) |
| T-12-04 | Denial of Service | unbounded compute via large `n_basis`/`n_comp`/`k` | low | accept | Local/CI single-session scope; defaults are bounded; caller controls its own process — documented as accepted for Phase 12 stdio scope |
</threat_model>
