# Plan 69-05 (gap closure): Wire extract_ragged_vecs into frechet_mean's spherical input

## Context

Phase 69 verification found FRE-03 partially unmet: `convert::extract_ragged_vecs` was
factored out of `pace_fpca_mod.rs` and validated (✓), but the ROADMAP clause "used by the
density/Fréchet inputs" is literally unmet — the frechet/density bindings use
`numpy2d_to_fdmatrix` / `PyReadonlyArray2` because the 0.33 API shapes are rectangular.

**User decision:** close the gap by routing `frechet_mean`'s **spherical** sample — a list
of (d,) 1-D unit vectors, which is exactly the `Vec<Vec<f64>>` shape `extract_ragged_vecs`
produces — through the shared helper. This is a natural, non-forced use that both satisfies
the contract and consolidates the list-of-1D-arrays extraction through the shared utility
(the purpose of factoring it out). Behavior must be unchanged (same unit-norm validation,
same result).

## Task 1 — Route the spherical sample through convert::extract_ragged_vecs

<read_first>
- src/frechet_mod.rs (the frechet_mean spherical arm + its per-object PyReadonlyArray1 extraction + unit-norm validation + the spherical_object_from_numpy helper)
- src/convert.rs (extract_ragged_vecs signature: `pub fn extract_ragged_vecs(list, caller_name: &str) -> PyResult<Vec<Vec<f64>>>`)
- src/pace_fpca_mod.rs (an existing caller, for the call convention)
</read_first>

<action>
In the `"spherical"` arm of frechet_mean (and its input-marshalling helper), replace the
per-item `item.extract::<PyReadonlyArray1<f64>>()` loop that builds the spherical objects
with a single call to `crate::convert::extract_ragged_vecs(objects, "frechet_mean")`, which
returns `Vec<Vec<f64>>`. Then, per vector: keep the existing unit-norm validation (raise
PyValueError if not unit-norm within the current tolerance) and the existing `d`-inference /
consistency checks (all vectors same length d; raise ValueError on ragged/mismatched d since
a spherical sample must be uniform-dimension), and construct the SphericalSpace objects
exactly as before. Net behavior is identical — only the extraction path changes to the
shared helper. Do NOT change the SPD/correlation arms (they take (d,d) matrices, a different
shape). Do NOT change the density_fda module.
</action>
