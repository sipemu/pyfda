## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → `fdars_method_references` handler | Untrusted `method: str` string crosses into the tool; used to split a module prefix and to key `callable_index`. |
| Handler → package data (`importlib.resources`) | The handler reads committed JSON from the installed `fdars` package; no filesystem path is taken from the caller. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-82-01 | Tampering | `method` module prefix → resource path | medium | mitigate | Frozenset-gate the module against `_REFERENCES_MODULES` (plus `_Fdata`) BEFORE any load; the resource name is a fixed literal (`_references_map.json` / `_capability_map.json`), never derived from caller input — no path traversal reachable (T-78-08 discipline). |
| T-82-02 | Information disclosure | Return payload | high | mitigate | LLM-free contract: no `provider`/`model` keys, no advisor/provider import in the handler body — asserted by the (C) AST-walk guard. Only committed, public paper metadata is projected (title/authors/year/doi/url/type/cross_language/curated); internal `notes` are omitted. |
| T-82-03 | Denial of service | JSON load per call | low | accept | Two small committed JSON files (~1.4k lines) read per call; no network, no unbounded recursion. Acceptable cost, consistent with `fdars_list_capabilities`. |
| T-82-04 | Repudiation / integrity drift | `_REFERENCES_MODULES` vs `_CAPABILITY_MODULES` | medium | mitigate | The (D) three-way frozenset-mirror guard (`_REFERENCES_MODULES == _EXPECTED_REFERENCES_MODULES == _CAPABILITY_MODULES`) fails any future edit that silently desyncs the module surface. |

No package-manager installs in this phase (`T-{phase}-SC` not applicable — no npm/pip/cargo install task).
