\section{Capability Tour}
\label{sec:capabilities}

\texttt{fdars} exposes \npubliccallables{} public callables across
\nsubmodules{} submodules, covering the full breadth of functional data
analysis methods surveyed in Table~\ref{tab:comparison}.
The \ncoverage{} callables backed by at least one curated peer-reviewed
reference are tracked in the machine-readable scientific-provenance layer
(Section~\ref{sec:advisor}).

Each method family in \texttt{fdars} follows the same boundary convention
described in Section~\ref{sec:design}: the user constructs or passes an
\texttt{Fdata} object (or a NumPy array directly for lower-level calls), which
the PyO3 binding converts to an \texttt{FdMatrix}, forwards to
\texttt{fdars-core}, and converts back to a NumPy result.  High-level
\texttt{Fdata} methods wrap this boundary transparently.  The scikit-learn
estimator layer (Section~\ref{subsec:sklearn}) exposes the same methods as
stateless \texttt{fit}/\texttt{transform} objects for pipeline composition.

The following minimal, executable snippets walk one representative per method
family; each is sourced from a script that runs against the live \texttt{fdars}
API and has its output deterministically captured (see
\texttt{paper/code/gen\_snippets.py}).  The snippets serve as both
documentation and regression tests: the CI drift gate (\texttt{make
paper-check}) verifies that regenerating them produces no diff against the
committed sources.

\subsection{Basis Representation and Smoothing}

fdars provides B-spline and Fourier basis expansions for functional data via
\texttt{fdars.basis}.
\texttt{fdata\_to\_basis\_1d} returns a \texttt{(coefficients, n\_basis)} tuple,
while \texttt{smooth\_basis\_gcv} selects the smoothing penalty via
generalised cross-validation and returns a dict including the fitted
curves, AIC, BIC, and effective degrees of freedom:

\input{snippets/basis}

\texttt{fdata\_to\_basis\_1d} projects each curve onto a fixed-size basis and
returns the coefficient matrix alongside the basis count, whereas
\texttt{smooth\_basis\_gcv} additionally \emph{chooses} the smoothing penalty by
minimising the generalised cross-validation score, trading data fidelity against
roughness.  Figure~\ref{fig:tour-basis} overlays five raw growth curves with
their GCV-selected B-spline reconstructions: the fitted curves follow the
observations closely while suppressing sampling noise, neither interpolating
every point nor flattening genuine curvature.  The returned AIC/BIC and
effective degrees of freedom quantify this fit--complexity balance for model
comparison.

\subsection{Depth and Outlier Detection}

Functional depth ranks observations by centrality relative to the full
sample~\citep{fraiman_muniz_2001}.
fdars offers modified band depth, Fraiman--Muniz depth, random Tukey depth,
and mode depth via the \texttt{Fdata.depth()} method.
The \texttt{fdars.outliers} submodule adds shape-, magnitude-, and
amplitude-based outlier detection via MUOD~\citep{dai_genton_2019}:

\input{snippets/depth}

Depth assigns each curve a centrality score relative to the whole sample; the
curve of maximum depth is the functional median.  MUOD complements this by
decomposing atypicality into three indices---shape, magnitude, and
amplitude---so that a curve unusual in \emph{form} is flagged separately from one
merely shifted in \emph{level}.  Figure~\ref{fig:tour-depth} shades each growth
curve by its Fraiman--Muniz depth (deeper curves drawn more opaque), highlights
the functional median, and marks the MUOD-flagged curves in red.  Read honestly,
depth is a sample-relative ordering and the outlier flags are cutoff-dependent
\emph{candidates} for inspection rather than definitive verdicts.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.82\linewidth]{figures/tour_depth}
  \caption{Growth curves shaded by Fraiman--Muniz depth (deeper curves more
  opaque).  The deepest curve (orange) is the functional median; curves flagged
  by MUOD as shape, magnitude, or amplitude outliers are drawn in red.}
  \label{fig:tour-depth}
\end{figure}

\subsection{Functional PCA and Sparse/Irregular FPCA}
\label{sec:fpca-snippet}

Dense FPCA is available via \texttt{Fdata.to\_pc()}, which returns scores,
rotation, singular values, and centred data.
For sparse or irregularly observed longitudinal data fdars provides PACE
(principal analysis by conditional expectation) through
\texttt{fdars.pace\_fpca.irreg\_fdata\_from\_lists} (the \texttt{PyIrregFdata}
container) and \texttt{fdars.pace\_fpca.pace\_fpca}~\citep{yao_muller_wang_2005}.
This distinguishes fdars from peer libraries that support dense FPCA only:

\input{snippets/fpca}

The dense path returns scores, the eigenfunction \texttt{rotation} matrix, and
singular values; the PACE path recovers the same structure from curves observed
at subject-specific, irregularly spaced times.  The most useful way to read an
FPCA fit is through its \emph{modes of variation}: the mean curve perturbed by
$\pm 2$ standard deviations along each eigenfunction.
Figure~\ref{fig:tour-fpca} shows the first two for the growth data---the
dominant component is an overall size/level mode, while the second is a timing
contrast that crosses near mid-adolescence, corresponding to \emph{when} the
pubertal growth spurt occurs.  The percentage in each panel title is the live
share of variance that component explains.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth]{figures/tour_fpca}
  \caption{First two FPCA modes of variation: the mean growth curve (grey)
  perturbed by $\pm 2$ standard deviations along each principal eigenfunction.
  PC1 is an overall-size mode; PC2 is a growth-timing contrast.  Variance shares
  are computed live from the singular values.}
  \label{fig:tour-fpca}
\end{figure}

\subsection{Clustering}

Functional $k$-means~\citep{bouveyron_jacques_2011} partitions observations by
minimising within-cluster $L^2$ distance in the curve space.
\texttt{fdars.clustering.kmeans\_fd} accepts a fixed random seed for
deterministic results and returns cluster assignments, centroids,
total within-cluster sum of squares, and a convergence flag:

\input{snippets/clustering}

Each iteration assigns every curve to its nearest centroid in $L^2$ and
recomputes centroids as within-cluster mean curves, until the assignment
stabilises.  Figure~\ref{fig:tour-clustering} colours the growth curves by their
cluster label and overlays the three centroids: the partition separates
primarily by overall growth level and attained final height.  As with any
$k$-means, the number of clusters $k$ is supplied by the user and the result is
a descriptive summary of the sample's dominant variation---not evidence of
discrete underlying subpopulations.  The fixed \texttt{seed} makes the
initialisation, and hence the reported partition, reproducible.

  \caption{Functional $k$-means ($k = 3$, fixed seed): thin curves are cluster
  members, bold curves the cluster centroids.  Cluster sizes are shown in the
  legend.}
  \label{fig:tour-clustering}
\end{figure}

\input{snippets/classification}

\subsection{Regression}

\texttt{fdars.regression} covers scalar-on-function (SoF) regression via
functional linear models with FPCA projection (\texttt{fregre\_lm}), PLS
(\texttt{fregre\_pls}), and robust variants, as well as function-on-function
(FoF) regression via \texttt{fof\_regression}~\citep{yao_muller_wang_2005}.
The snippet demonstrates SoF regression on the Tecator near-infrared spectra
dataset, predicting fat content from 100-channel absorbance curves:

\input{snippets/regression}

\texttt{fregre\_lm} projects the predictor curves onto their leading FPCA
components, fits an ordinary linear model in that score space, and returns the
fitted values, residuals, the reconstructed coefficient function $\beta(t)$, and
the coefficient of determination.  Figure~\ref{fig:tour-regression} plots fitted
against observed fat content: points cluster tightly along the identity line,
with the scatter widening at high fat content where the sample thins.  The
$R^2$ shown in the figure is computed live from the fit.  PLS and robust
variants (for collinear or contaminated predictors) and function-on-function
regression share the same call convention.

\subsection{Functional Time Series}

The \texttt{fdars.fts} submodule implements functional time-series models
(FTSM) for data in which the observed unit is a curve indexed over time
(e.g.\ daily temperature profiles across years).
\texttt{ftsm\_forecast} takes the raw data matrix and grid directly and
returns multi-step-ahead curve forecasts:

\input{snippets/fts}

FTSM decomposes the observed curve sequence into functional principal
components, models the temporal dynamics of the resulting score series, and
reconstructs the next $h$ curves from the forecast scores.
Figure~\ref{fig:tour-fts} overlays the three forecast curves on the input
sequence: the forecasts retain the dominant seasonal temperature profile shared
by the input curves.  Because the reconstruction is low-rank, the forecasts
capture the leading modes of variation rather than fine day-to-day fluctuation
---the honest cost of the dimension reduction that makes curve forecasting
tractable.
The curves shown are the Canadian weather stations, used here as an illustrative
ordered sequence rather than a genuine temporal index; the forecast therefore
demonstrates the \texttt{fdars.fts} interface rather than a substantive
prediction.  Case Study~\ref{subsec:cs3-fts} applies the same method with this
limitation stated in full.

\begin{figure}[htbp]

  sequence (grey, the 35 Canadian weather stations), reconstructed from three

\subsection{Statistical Process Monitoring}

\texttt{fdars.spm} adapts Hotelling $T^2$ and squared prediction error (SPE)
control charts to functional data by first estimating in-control variation
via \texttt{spm\_phase1} and then monitoring new batches with
\texttt{spm\_monitor}.
Phase-1 output components (mean, loadings, weights, eigenvalues, and control
limits) are passed as explicit positional arguments to the monitoring function:

\input{snippets/spm}

Phase~1 characterises in-control variation from a reference set of curves and
derives the $T^2$ and SPE control limits; Phase~2 then scores each new curve on
these two statistics and flags any that exceed a limit.
Figure~\ref{fig:tour-spm} shows the resulting $T^2$ chart, with out-of-control

\subsection{Conformal and Tolerance Bands}

\texttt{fdars.tolerance} constructs simultaneous tolerance bands for functional
data via bootstrap FPCA~\citep{febrerobande_fdausc_2012}.
\texttt{fpca\_tolerance\_band} returns upper/lower band curves, a centre curve,
and the half-width vector; a fixed \texttt{seed} argument makes the bootstrap
resampling reproducible:

\input{snippets/tolerance}

The band is built by repeatedly resampling an FPCA model and calibrating a
half-width so that the resulting envelope is expected to contain the target
fraction of curves \emph{simultaneously} across the whole grid---a stronger
guarantee than a pointwise interval.  Figure~\ref{fig:tour-tolerance} draws the
95\% band over the growth sample: most curves fall inside it, and the band
widens through adolescence where between-subject spread is largest.  The
coverage is a bootstrap estimate rather than an exact finite-sample guarantee,
and the fixed \texttt{seed} pins the reported band.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=0.82\linewidth]{figures/tour_tolerance}
  \caption{Bootstrap-FPCA 95\% simultaneous tolerance band (shaded) with its
  centre curve, drawn over the growth sample.  The band widens where
  between-subject variability grows.}
  \label{fig:tour-tolerance}
\end{figure}

\subsection{Metrics, Density, and Fr\'echet Analysis}

\texttt{fdars.metric} provides $L^p$ pairwise distance matrices
(\texttt{lp\_self\_1d}) and dynamic time warping (\texttt{dtw\_self\_1d}) for
functional observations.
Beyond pairwise distances, fdars also provides density-FDA methods (LQD FPCA
and Wasserstein barycenters) in \texttt{fdars.density\_fda}, and Fr\'echet
means, regression, and ANOVA for object-valued data in
\texttt{fdars.frechet}~\citep{petersen_muller_2019}; see
Table~\ref{tab:comparison} for the full peer comparison.
The snippet illustrates the metric family representative:

\input{snippets/metric}

\texttt{lp\_self\_1d} integrates the pointwise $L^p$ difference between every
pair of curves, while \texttt{dtw\_self\_1d} instead allows elastic time-warping
before measuring distance.  Figure~\ref{fig:tour-metric} renders the $L^2$
distance matrix as a heatmap: the dark diagonal is each curve's zero
self-distance, and the off-diagonal block structure exposes groups of mutually
similar growth trajectories.  Such a distance matrix is the shared input to
downstream methods---clustering, $k$-NN classification, and multidimensional
scaling---so the metric family underpins much of the rest of the tour.

\subsection{Elastic Alignment}

\texttt{fdars.alignment} implements elastic registration under the square-root
slope function (SRSF) framework~\citep{srivastava_et_al_2011}.
\texttt{karcher\_mean} estimates the Karcher mean curve by iteratively
aligning observations and re-estimating the mean; the returned dict includes
the aligned data matrix, phase-warping functions ($\gamma$), and a convergence flag:

\input{snippets/alignment}

Elastic registration separates two kinds of variation that ordinary averaging
conflates: \emph{amplitude} (how high a feature is) and \emph{phase} (when it
occurs).  \texttt{karcher\_mean} iterates between warping each curve onto the
current mean under the SRSF metric and re-estimating that mean.
Figure~\ref{fig:tour-alignment} contrasts ten growth curves before and after
alignment: post-registration the shared features line up, tightening the bundle,
while the warping functions $\gamma$ record exactly how each curve's time axis
was deformed.  Alignment therefore trades phase for amplitude---the $\gamma$
functions are not a nuisance by-product but a first-class output describing the
phase variation that was removed.

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth]{figures/tour_alignment}
  \caption{Elastic SRSF registration of ten growth curves, before (left) and
  after (right) Karcher-mean alignment.  The red curve is the estimated Karcher
  mean; alignment tightens the sample by removing phase variation.}
  \label{fig:tour-alignment}
\end{figure}

\subsection{Grounded AI Advisor (LLM-Free Diagnostics)}

\texttt{fdars.advisor.build\_diagnostics} computes method-specific structured
diagnostics from any fdars result dict in a fully offline, deterministic
manner---no LLM provider is required.
The LLM-assisted \texttt{advise()} function takes these diagnostics and a
user-specified task description and queries a configured language model to
generate grounded parameter recommendations; it is described further in
Section~\ref{sec:advisor}.
The snippet demonstrates the offline diagnostic step for FPCA:

\input{snippets/advisor_diag}

The diagnostic reduces a full result dict to the small set of scalars a
practitioner would actually inspect---here, the per-component and cumulative
variance explained.  Figure~\ref{fig:tour-advisor} plots exactly these
quantities as a scree chart: the first component dominates and the cumulative
curve saturates quickly, which is the concrete signal the advisor uses to
recommend how many components to retain.  Because every number is computed from
the data rather than generated by a language model, the resulting guidance is
\emph{grounded}: the optional \texttt{advise()} step passes these diagnostics to
an LLM only to phrase and contextualise a recommendation the numbers already
support (Section~\ref{sec:advisor}).
