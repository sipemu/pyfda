\section{Comparison with Related Software}
\label{sec:comparison}

Table~\ref{tab:comparison} compares \textbf{fdars} with general-purpose
functional data analysis software.  \textbf{fdars} is the broadest of the
Python packages compared: it covers the analytical pipeline from representation
and alignment through depth, clustering, classification, regression, functional
time series, statistical process monitoring, conformal prediction, and
density/Fr\'{e}chet analysis in a single package with a scikit-learn-compatible
API.  The table deliberately omits single-purpose packages that are strong in
one area---\texttt{fdapace}, \texttt{ftsa}, \texttt{funcharts},
\texttt{frechet}, \texttt{fdasrvf}, \texttt{roahd}, and \texttt{fdaoutlier}
(introduced in Section~1)---several of which match or exceed \textbf{fdars} in
depth within their niche; three of them (\texttt{fdapace}, \texttt{fdasrvf},
\texttt{roahd}), together with \texttt{fda.usc}, serve as references for the
agreement checks in Section~\ref{sec:validation}.  The R column therefore understates the
R ecosystem as a whole: what it lacks is a single package, or a single data
model, spanning all rows.  Conversely, the mature peers have strengths the table
does not capture, such as scikit-fda's documentation and the mixed-model depth
of \texttt{refund}.
Where capability evidence for peer packages was ambiguous, cells were rated
down (partial rather than $\checkmark$, --- rather than partial).  Because this
favours \textbf{fdars}, every non-\textbf{fdars} cell is sourced, with the
function names or documentation it rests on, in
\texttt{paper/comparison\_evidence.md}, so that readers can check it.

Table~\ref{tab:comparison} summarises the capability coverage of \textbf{fdars}
against the most widely used Python and R functional data analysis packages and
the historical MATLAB tools that define the field.
